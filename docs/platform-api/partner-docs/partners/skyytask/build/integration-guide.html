01 · The idea

Replace the code-and-Drive handoff with a branded delivery

Today a finished job ends with a one-time code and a Google Drive link. With ShootPortal, the pilot uploads inside the SkyyTask app, the client opens a private SkyyTask-branded portal, and SkyyTask is told about every step automatically.

Today
Complete JobOTP codeGoogle Drive link
  • Clients juggle a code and leave the app for Drive
  • Unbranded folders; no view or download tracking
  • Pilots manage folders and sharing by hand
With ShootPortal
Transfer deliverablesUploadBranded client portal
  • One tap in the SkyyTask app opens the upload screen, already linked to the job
  • Clients get a private link: no codes, no accounts, no passwords
  • SkyyTask sees submitted, viewed and downloaded as they happen
  • Everything carries SkyyTask's logo, colors and (optionally) domain
A

Who's involved

SkyyTask servers

Create jobs in ShootPortal and receive status updates. Hold the secret key.

SkyyTask app

Shows the “Transfer deliverables” button and opens the upload screen.

The pilot

Uploads files from phone or computer. No ShootPortal account needed.

The client

Views and downloads through a private, branded link.

ShootPortal

Stores, organizes and delivers the media, and reports back.

B

Principles we're designing around

SkyyTask stays in control

Jobs, chat, payments and the client relationship stay in SkyyTask. ShootPortal is the delivery layer only. No quotes, invoices or payment screens appear anywhere.

Branded end to end

Upload screen, portal and emails use SkyyTask's name, logo and colors, with a small “Powered by ShootPortal” mark.

Built for big files and bad signal

Uploads go in small chunks straight to secure storage. If the connection drops or the app closes, it resumes instead of starting over.

Private by default

Every link is private and expires. Secret keys never touch a phone. Every status message is signed so SkyyTask can trust it.

Works for marketplace and white-glove jobs alike. The same delivery can be created automatically by SkyyTask's app, or by SkyyTask staff signing in to ShootPortal directly for hand-managed enterprise jobs.

In one sentence
SkyyTask keeps the job, the chat and the client relationship. ShootPortal quietly handles the files: upload, storage, a beautiful branded handoff, and a signed receipt for every step.

04 · Who does what

A small build for SkyyTask, the heavy lifting on ShootPortal

SkyyTask's team builds

1

Create the job in ShootPortal

One server call when a job is accepted or completed (your choice).

2

The “Transfer deliverables” button

Ask ShootPortal for an upload link and open it in the app's in-app browser.

3

A status receiver

A small endpoint that checks each update's signature and moves the job forward.

4

Optional: share the link in chat

If SkyyTask prefers to message the client itself.

ShootPortal provides

  • The API, a full test sandbox and test keys
  • The branded, resumable upload screen (phone and desktop)
  • Secure storage for every file type, 90 days included
  • The private, branded client portal and emails
  • Signed, automatically retried status updates
  • Developer Guide, API reference and a Postman collection
  • A live demo partner to try the full flow before writing code
  • Direct founder support during integration
A

Information exchanged

SkyyTask sends
Job: your job number, title, address
Clients: name, email (phone optional), your client ID
Pilot: name, email, your pilot ID
Nothing else. No prices, payments or private job details.
ShootPortal sends back
Links: the upload link and private portal links
Status: submitted, published, viewed, downloaded, expired
Details: file counts, total size, expiry date
Price of each delivery, the moment it's submitted
B

Choices SkyyTask makes

Who notifies the client

ShootPortal email, SkyyTask's own chat, or both.

Publish automatically or review first

Go live on submit, or approve each delivery.

Web address

skyytask.shootportal.app to start, or your own, e.g. deliver.skyytask.com.

Pilot receipt email

Optional “Delivery received” confirmation.

C

To decide together

  • Create the ShootPortal job when it's accepted, or at Complete Job?
  • Which status should trigger pilot payouts: submitted, viewed or downloaded?
  • Is a one-time code still needed, or is a private link enough?
  • App technology, and in-app browser vs. web view for the upload screen
  • Typical monthly job volume and delivery sizes by job type
  • Enterprise file types to support first (thermal, GeoTIFF, LAS/LAZ, KMZ, reports)
D

Works with any app technology

iOS

Open the upload link in an in-app Safari view (SFSafariViewController).

Android

Open it in Chrome Custom Tabs.

React Native / Flutter

Use the framework's in-app browser plugin.

Web & desktop

Open it in a new tab or window; it returns when done.

05 · Included, security & next steps

Everything in one delivery layer

Branding & domain

Logo, colors, sender name, your own web address.

Resumable uploads

Multi-GB files from a phone, resumed after drops.

Every file type

Photo, video, PDF, thermal, GeoTIFF, LAS/LAZ, KMZ, RAW.

90-day storage

Included per delivery; extend for archives.

Unlimited recipients

Every stakeholder gets their own private link.

View & download tracking

Know when each client opened and downloaded.

No commercial screens

No quotes, invoices or payments anywhere.

Founder support

Direct line during integration and launch.

A

Security & privacy

  • Secret keys stay on SkyyTask's servers. Phones only ever get a one-job, short-lived upload link.
  • Signed status updates. Each message carries a tamper-proof signature SkyyTask verifies.
  • Private, expiring links for every client; files are never public.
  • Isolated data. SkyyTask's jobs live in their own walled-off space.
  • Minimal data. Names and emails only. No prices, payments or job financials.
B

Test mode vs. live mode

Test

A full copy for building and demos. Nothing is billed; emails go only to addresses you approve.

Live

Real pilots and clients. Same code: just swap in a live key.
